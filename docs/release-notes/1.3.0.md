## Changes

### Remote production (milestone 9, §13)

- The gallery (master) rides up to four far-side mixers (slaves) over a
  WebSocket on the slave's web port (`/api/v1/link`, pre-shared
  `MIXER_LINK_TOKEN`): each far side is a layer of the console (strips, inputs,
  auxiliaries, meters at 10 Hz); fader, mute, send and snapshot recall go back.
  Audio stays on MXL.
- `POST /api/v1/remotes/<id>/return` publishes the gallery's mix-minus of a bus
  without the far-side contribution (`ret-s1` …) and builds an in-ear per
  far-side voice there (`iem-<voice>`: the other voices plus that return,
  mixed where the people are, not delay-compensated).
- The slave holds its mix when the master goes; with
  `MIXER_LINK_TAKEOVER=deny` local changes are refused (400) until a master is
  back. The master's own commands are never refused.
- One master per slave at a time. Both sides ping every second and close the
  link after 5 s of silence; the master reconnects every 2 s.
- Commands are numbered and acknowledged per connection, at most once (not
  resent). Message types a peer does not know are ignored, so versions
  interoperate.
- Metrics `remote_link_up{peer}`, `remote_link_rtt_ms{peer}`.

### Logic editor (milestone 8, part 2, §11)

- **Typed ports:** `boolean`, `number`, `level` (dB), `event` and `string`. Wires
  are type-checked: booleans, numbers and levels convert into each other (on is
  ≥ 0.5), a value into an event fires when it turns on, anything but an event
  into a string; a string feeds only a string. Every 1.2.0 graph stays valid.
- **New blocks.** Inputs: `text`, `trigger` (an HTTP trigger), `pfl`, `loudness`
  (momentary, short-term, integrated, range, true peak), `nmos-receiver` and
  `nmos-sender` (active), `link` (a remote-link peer is up). Logic: `toggle`,
  `counter`, `math` (`add`, `sub`, `mul`, `div`, `min`, `max`), `scale`, `map` (a
  curve), `select`, and `compare` with `ge`, `le`, `ne`. Actions: `set-vca`,
  `set-param` (any node parameter the DSP smooths, validated against the node and
  clamped to its range), `set-pfl`, `set-talk`, `set-publish`, `set-monitor`,
  `loudness-control`, `tsl-out` (TSL UMD 5.0 over UDP to `TSL_OUT_TARGET`), `log`
  (a log line and a message on the events WebSocket). `set-fader` and `set-vca`
  take `ramp_ms`.
- **Macros:** sub-graphs with exposed ports, used as blocks, saved in the show
  (`logic_macros`), evaluated as if inlined, each instance with its own state;
  recursion and loops through them are refused.
- **API for the canvas:** `GET /api/v1/logic-blocks` (every type with its
  parameters and ports), `PUT /api/v1/logic/<id>` (the whole graph),
  `POST /api/v1/logic-batch` (graphs and macros as one change) and
  `POST /api/v1/logic-validate`, all with a `revision` check (409 when stale);
  `/api/v1/logic-macros`; `POST /api/v1/logic/<id>/trigger/<block>`. A refused
  graph answers 400 with `issues` naming the graph or macro, block, port and
  wire. Graphs answer with `ports`, typed `values` and their last 20 `actions`.
- **The editor (Logic tab, §11.3):** a palette from the block catalog (drag or
  click), cables between typed, colour-coded ports (refused while drawn when the
  input cannot take them), zoom, pan and a minimap, multi-select, copy and paste
  with cables (also into another graph), undo and redo of every edit (each one
  atomic batch; an undo over another client's change is refused), group into a
  macro with chosen exposed ports, open a macro (breadcrumb back) and ungroup.
  A refused edit shows its issues as red markers on the blocks, ports and the
  dashed cable. Every block shows its live value; the last actions are listed,
  dry-run ones marked. New graphs start in dry run (LIVE, DRY RUN or OFF in the
  toolbar; undo never changes it); a new block gets no target by itself (amber
  until chosen; an input without one reads off, 0 or the floor); paste, group,
  ungroup, undo and redo in a live graph ask first, since re-made actions act at
  once and re-made blocks start with empty memory.
- **Execution:** compiled once per change (macros inlined) and run in
  topological order on the 10 ms control tick; nothing on the DSP thread. Dry
  run now lists its actions (in the graph's `actions`, the log and the events
  WebSocket) instead of computing silently. An action whose input has no wire
  never runs.
- Fixed: a logic change that rewires the plan (publish, PFL, talk, monitor
  source, snapshot recall) could be lost when an API change staged during its
  fade; they now share one change lock.
- `mix.json` is written within about 0.6 s after fader and parameter changes
  (from the API or from logic), at once after other changes and at SIGTERM. The
  `/config` volume no longer sees up to 100 writes a second; a crash loses at
  most the last 0.6 s of fader moves.
- **The webhook block's body changed:** it posts `{"graph", "block",
  "value": 1}` (1.2.0 posted `{"value": 1}`). A receiver that refused unknown
  fields must accept `graph` and `block`.
- Safety limits: an action runs at most every 20 ms (TSL 50 ms, a webhook
  100 ms, a change that rewires the plan 250 ms); at most 8 webhook posts run at
  once. TSL indexes that go away are switched off (three times, a second apart,
  and all of them at SIGTERM). An action fed only by an unconnected macro input never runs; NaN at a
  fader is no change and +∞ is its maximum.
- **Security:** the HTTP trigger has no authentication, like the rest of the
  API: anyone who reaches the web port can fire a graph's `trigger` blocks. An
  outside system that should fire one needs a path through the platform's
  ingress with its own authentication.

### Platform readiness

- Real time as uid 1000: the image's file capability plus `SYS_NICE` in the
  container gives the DSP thread `SCHED_FIFO` (`MIXER_RT_PRIORITY`); the start log
  lists the effective capabilities, a refused `SCHED_FIFO` is a warning, and
  `dsp_realtime` says what the thread got. Without `SYS_NICE` the mixer starts
  with `SCHED_OTHER`.
- The DSP thread takes the last CPU whose SMT siblings are all in the pod (a
  whole core).
- Start-up checks (exit codes below): the scan path must exist, the state
  directory must be writable, the output domain must be directly below the scan
  path, every port is checked before the output domain is created, and a failed
  start removes a domain it created.
- An existing `domain_def.json` with another id is kept and used (a warning)
  and never removed. `domain_def.json` and `options.json` are created
  atomically and only once: a private temp file (created exclusively, with a
  random UUID name) is hard-linked into place, which never replaces an existing file. Several
  processes creating the same domain at once all succeed, and exactly one of
  them counts as having created it. The soft open-files limit is raised (at
  most 65536).
- Fixed: `mxl-mixer-tone` writers started together on a new domain could exit
  with "not a valid domain definition".
- An unreadable `domain_def.json` reports the real error (e.g. "cannot read
  …: Permission denied"); a half-made domain (`options.json` failed after
  `domain_def.json` was written) is removed by the failed start.
- Metrics `dsp_realtime`, `logic_ticks_total`, `logic_actions_total{graph}`;
  `# HELP`/`# TYPE` for every family.
- A failed logic webhook is a warning (without the URL's credentials, query
  and fragment).

## Settings

Environment first, then `MIXER_CONFIG_FILE`, then the defaults; an invalid value
exits with 78. **New in 1.3.0:** `MIXER_LINK_ROLE`, `MIXER_LINK_TOKEN` (a
secret: give it from a Kubernetes Secret; never shown or exported),
`MIXER_LINK_PEERS`, `MIXER_LINK_TAKEOVER`; `TSL_OUT_TARGET` (`host:port`, a DNS
name or an IP address, resolved again every 30 s) and `TSL_OUT_SCREEN` for the
logic editor's TSL output. **Stricter in 1.3.0:**
`MXL_DOMAIN_SCAN_PATH` (must exist), `MXL_OUTPUT_DOMAIN_DIR` (directly below the
scan path), `MXL_OUTPUT_DOMAIN_ID` (another id on disk is kept, not exit 78),
`MXL_CLEANUP_ON_EXIT` (never a kept domain), `MIXER_STATE_DIR` (must be
writable). Every setting:

## Exit codes

| Exit code | Meaning |
| --- | --- |
| 0 | stopped by Ctrl-C |
| 75 | a port cannot be bound, **libmxl cannot be loaded (was 78)**, or the DSP thread cannot start; every port is checked before the output domain is created |
| 78 | invalid configuration: an invalid setting (the new `MIXER_LINK_PEERS` is checked strictly), **`MXL_DOMAIN_SCAN_PATH` missing**, **`MXL_OUTPUT_DOMAIN_DIR` not directly below it**, **`MIXER_STATE_DIR` not writable**, an unreadable `domain_def.json`, an output domain that cannot be created, the NMOS node that cannot be built. **An output domain id clash is no longer 78**: the domain is kept and used, with a warning. |
| 143 | SIGTERM: media stopped, MXL released, node deregistered, own domain removed with `MXL_CLEANUP_ON_EXIT=true` (never a kept one), within `SHUTDOWN_TIMEOUT_S` |

## What the platform must set

- **CPUs:** Guaranteed QoS (requests = limits), an **even** number of whole
  CPUs, the static CPU manager. **`cpu: "4"` is the recommendation** (two
  physical cores: the DSP thread has one, the other threads the other).
  `"2"` (one core) is the minimum: the DSP CPU's sibling then runs the mixer's
  other threads (the meters, the VAD, the preview encoders, the tokio workers).
  That is not measured on hardware. `reservedSystemCPUs` should keep the
  system daemons off the pod's cores; the other risks to the DSP core are IRQs
  on its CPUs and its sibling handed to another Guaranteed pod (unpinned pods
  never use exclusive CPUs). `full-pcpus-only` prevents the last one; it is
  recommended, not required.
- **Real time:** `MIXER_RT_PRIORITY=49` and
  `securityContext.capabilities: {drop: [ALL], add: [SYS_NICE]}`,
  `allowPrivilegeEscalation: false`, uid 1000.
- **Preview:** the shared MediaMTX — `PREVIEW_PUBLISH_URL`
  (`rtsp://mxl-mediamtx.mxl-platform.svc.cluster.local:8554`),
  `PREVIEW_PATH_PREFIX` (`<production>/<function>`), `PREVIEW_WHEP_URL`,
  `PREVIEW_HLS_URL`, `MEDIAMTX_API_URL` (`…:9997`). With them no built-in
  MediaMTX runs and its three ports stay closed. Browser talkback publishes by
  WHIP to `<PREVIEW_WHEP_URL>/<PREVIEW_PATH_PREFIX>/talkback-<client>/whip`
  (`<client>` is the browser's id, a-z, 0-9 and '-'), which matches the shared
  MediaMTX's publish rule `^.+/talkback-[^/]+$`. The mixer cannot send WHIP
  credentials (no setting, no header from the browser): if the platform adds
  publish credentials, the mixer needs a change first.
- **Volumes:** the MXL root as a hostPath at `/Volumes/mxl`
  (`MXL_DOMAIN_SCAN_PATH`), `MXL_OUTPUT_DOMAIN_DIR` a directory directly below
  it, `MXL_OUTPUT_DOMAIN_ID`, and a writable PVC at `/config`. The domain
  filesystem must support hard links (tmpfs, ext4 and xfs do); hidden
  `.domain_def.json.<uuid>.tmp` and `.options.json.<uuid>.tmp` files may appear there briefly.
- **Identity:** `NMOS_HOST_ADDRESS` the pod IP; `HOST_ID`, `NMOS_SEED`,
  `NMOS_LABEL`, `NMOS_TAGS` stable per instance; `NMOS_REGISTRY_ADDRESS` and
  `NMOS_REGISTRY_PORT`; `NMOS_QUERY_ADDRESS` and `NMOS_QUERY_PORT` when the
  Query API is not at the registry address and the next port (their defaults);
  `NMOS_DNS_SD=false`.
- **Shutdown:** `terminationGracePeriodSeconds` ≥ 20 (above
  `SHUTDOWN_TIMEOUT_S`, 10).
- **Nodes:** the kernel TAI offset (CLOCK_TAI = UTC + 37 s). Without it every
  MXL time is off, but `/readyz` does not wait for it: the pod goes Ready
  anyway. Watch `timing_trusted` (in the `/readyz` details and the metric) and
  the error line `timing untrusted: CLOCK_TAI - CLOCK_REALTIME is …` in the log.
- `TSL_OUT_TARGET` only when a show's logic graphs drive tally displays
  (`tsl-out` blocks). A NetworkPolicy must allow the pod's UDP egress to that
  host and port (the mixer sends from an ephemeral port), and HTTP(S) egress to
  the logic webhooks' hosts if graphs use them.
- `WIDGET_FRAME_ANCESTORS` with the production designer's origin;
  `TSL_ENABLE=true` with the tally calculator's TSL target, for
  audio-follows-video.
- **After the start, check** `dsp.scheduling` in `GET /api/v1/status` and
  `mxl_audio_mixer_dsp_realtime` 1 (the log line
  `effective capabilities: sys_nice`). `dsp.scheduling` should read:
  - with `cpu: "4"`: `a core of its own (its other CPUs kept free)` (or
    `a core of its own (no SMT)` on a node without SMT);
  - with `cpu: "2"`: `its core shared with the mixer's other threads (CPU n): no other core`,
    with n the DSP CPU's sibling;
  - `its core shared with CPU n, outside this process: another workload may slow it`
    is wrong: another workload has the sibling (also a warning in the log).

`deploy/k8s/deployment.yaml` is an example of all of it.

### The remote link (only with `MIXER_LINK_ROLE` set)

- `MIXER_LINK_TOKEN` from a Secret, the same on both sides.
- `MIXER_LINK_PEERS` is checked in every role (exit 78): `ws://` or `wss://`, a
  host, a valid port, no user or password, each slave once. A slave's id is its
  place in the list (`s1` first).
- `wss://` needs a TLS-terminating proxy or ingress in front of the slave's web
  port (the slave serves plain WebSocket). For a private CA, give the master
  `SSL_CERT_FILE` or `SSL_CERT_DIR` (they replace the system store). Over
  `ws://` the token travels in clear: a trusted network only.
- The master lists every configured slave from the start: one never reached
  shows `remote_link_up{peer="sN"} 0`. A slave has no `peer="master"` series
  until a master first connects. `remote_link_rtt_ms` is left out while a link
  is down.
- The master's `command`, `push` and `return` answer 409 while the far side is
  down and `command` 503 when 1024 commands wait (a stuck link), with a JSON
  `{"error": …}` body.
- A connection must send its hello within 5 s; a link message has at most
  4 MiB.

## Upgrade from 1.2.0

In place (the same `/config` and output domain):
- **The output domain rule:** `MXL_OUTPUT_DOMAIN_DIR` must be a directory
  directly below `MXL_DOMAIN_SCAN_PATH`, else exit 78. The default
  (`<scan path>/mixer-<8 hex>`) is; a custom one elsewhere (e.g.
  `/Volumes/mxl/production/mix1`) must move up one level. Moving it creates a
  new domain directory: the old one is not removed.
- **Exit codes:** libmxl missing is 75 (was 78). A missing scan path or an
  unwritable state directory is now 78 at start (before, the mixer ran and lost
  its changes). An output domain whose `domain_def.json` has another id is kept
  and used (was 78), and never removed on exit.
- Real time now works as uid 1000 with `SYS_NICE` in the container's
  capabilities; check `dsp_realtime` after the upgrade.
- The settings, the show file and the IS-05 connections carry over unchanged.
  The remote link is off unless `MIXER_LINK_ROLE` is set.
- **Logic graphs** load unchanged (the show file stays version 1; a show that
  uses macros or the new blocks does not load on 1.2.0). Three changes: an
  action whose input has no wire no longer acts at the first tick (1.2.0 applied
  0, e.g. an unwired `set-mute` unmuted); `edge` is an event (its live value is
  how often it fired); live `values` are typed (booleans `true`/`false`, not
  1/0). `set-fader` blocks gain `ramp_ms` (10, as before) when saved.
