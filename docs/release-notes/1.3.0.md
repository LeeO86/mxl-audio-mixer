## Changed for the platform

- `SCHED_FIFO` works for the uid-1000 process with `SYS_NICE` in
  `capabilities.add` (the mixer raises its permitted file capability at start).
  New gauge `mxl_audio_mixer_dsp_realtime`.
- The DSP thread takes the last CPU whose SMT siblings are all in the pod.
- Start-up checks, in this order: `MXL_DOMAIN_SCAN_PATH` exists (78),
  `MIXER_STATE_DIR` is writable (78), libmxl loads (75), every port is free (75);
  only then the output domain is created, and a later failed start removes a domain
  it created.
- `MXL_OUTPUT_DOMAIN_DIR` must be directly below `MXL_DOMAIN_SCAN_PATH` (78); it is
  the only directory `MXL_CLEANUP_ON_EXIT` removes.
- An existing `domain_def.json` with another id is kept (a warning) instead of
  exit 78. `domain_def.json` and `options.json` are written atomically.
- The soft open-files limit is raised to the hard limit.
- New metrics `logic_ticks_total`, `logic_actions_total{graph}`; the remote-link
  metrics have `# HELP` and `# TYPE`.

## Exit codes

| Exit code | Meaning |
| --- | --- |
| 0 | stopped by Ctrl-C |
| 75 | a port cannot be bound, libmxl cannot be loaded (was 78), the DSP thread cannot start |
| 78 | an invalid setting, `MXL_DOMAIN_SCAN_PATH` missing or not a directory, `MXL_OUTPUT_DOMAIN_DIR` not directly below it, `MIXER_STATE_DIR` not writable, an unreadable `domain_def.json` |
| 143 | SIGTERM: media stopped, MXL released, node deregistered, own domain removed with `MXL_CLEANUP_ON_EXIT=true`, within `SHUTDOWN_TIMEOUT_S` |

## What the platform must set

- **CPUs:** Guaranteed QoS (requests = limits) with an **even** number of whole
  CPUs: `"2"` at least (one physical core: the DSP thread on one hardware thread,
  the mixer's other threads on its sibling), `"4"` preferred (the other threads on
  a core of their own). The kubelet's static CPU manager with `reservedSystemCPUs`
  covering the system daemons and unpinned pods. `full-pcpus-only` is recommended,
  not required: with an even request the static policy hands out whole cores when
  they are free. After the start, `dsp.scheduling` in `GET /api/v1/status` must
  say "a core of its own"; "outside this process" means another workload shares
  the DSP core (also logged as a warning).
- **Real time:** `MIXER_RT_PRIORITY=49` with
  `securityContext.capabilities: {drop: [ALL], add: [SYS_NICE]}`. The log says
  `effective capabilities: sys_nice` and `SCHED_FIFO 49`; `dsp_realtime` is 1.
- `NMOS_HOST_ADDRESS` = the pod IP; `HOST_ID`, `NMOS_SEED`, `NMOS_LABEL`,
  `NMOS_TAGS` per instance; `NMOS_REGISTRY_ADDRESS`/`NMOS_REGISTRY_PORT`;
  `NMOS_DNS_SD=false`.
- `MXL_DOMAIN_SCAN_PATH=/Volumes/mxl` (hostPath, type Directory),
  `MXL_OUTPUT_DOMAIN_DIR=/Volumes/mxl/<instance>`, `MXL_OUTPUT_DOMAIN_ID`,
  `MXL_CLEANUP_ON_EXIT=true`.
- A writable `/config` (`MIXER_STATE_DIR`); `SHUTDOWN_TIMEOUT_S=10` and
  `terminationGracePeriodSeconds` 20.
- The shared MediaMTX: `PREVIEW_PUBLISH_URL`, `PREVIEW_PATH_PREFIX`,
  `PREVIEW_WHEP_URL`, `PREVIEW_HLS_URL`, `MEDIAMTX_API_URL`. The mixer then starts
  no MediaMTX of its own; it publishes RTSP over TCP (interleaved), without
  credentials.
- `WIDGET_FRAME_ANCESTORS` with the production designer's origin.
- The API has no authentication: the web and NMOS ports stay on the pod network.
- The node's kernel TAI offset (CLOCK_TAI = UTC + 37 s).
