# mxl-audio-mixer 1.6.0 — release notes

The operators' second round of feedback from the Confluence page "Feedback MXL
Audio-Mixer": the console strip (A1–A13), menus, selection and views (B1–B11),
processing and DSP (C1–C8) and outputs as inputs (D1); plus the platform's bug
D-347: remote inputs that drop samples (D2) and the DSP deadline misses (D3).
Released 2026-11-06. Every item is listed in `CHANGELOG.md` with its ID.

## Upgrade and rollback — read first

- **Export the show before upgrading:** `GET /api/v1/config/export` (or keep a copy
  of `/config/mix.json`). An upgrade from 1.5.x is in place (the same `/config` and
  output domain).
- **Behaviour change (A5–A7): the surround panner is the strip's surround pan now,
  not a processing block.** A 1.5 show loads: an active panner becomes the strip's
  surround pan, its L/R pan is centred. What that changes per strip is in
  `load_warnings` (entries starting "1.5 show: ") and in a banner. Check shows with
  surround panners after the upgrade.
- **Behaviour change (D2): remote inputs get more delay.** The automatic input
  delay now covers the worst lag of the last 5 min plus a margin. In the lab a
  jittered remote flow went from 33 to 42 ms and stopped losing blocks. After one
  spike of 100 ms or more an input holds up to 150 ms (the
  `MIXER_INPUT_DELAY_MAX_MS` cap) for about 5.5 min. Readers of mixer outputs: the
  write delay grows with it (see 1.5.1).
- **Behaviour change of a metric (D3):** `dsp_deadline_misses_total` counts each
  skipped block once. 1.5 counted two per stall, so on the same host the numbers
  are about **half**: halve alerts on it.
- **Rollback to 1.5.1 keeps the show.** 1.6 saves `mix.json` (and the show history)
  in a form 1.5.1 loads: strips, buses, sends, direct outs (same flow and sender
  ids), auto-mixes and virtual outputs stay (measured). What 1.5.1 does not have is
  approximate or dropped there: surround pans and member offsets are gone, taps
  after the fader or a new block are moved to the nearest 1.5.1 point, inserts pass
  dry, extra direct outs and insert sends are not published, strip channels that
  read a bus or an output are silent, the named down-mixes are dropped.
- **Back to 1.6 after a rollback:** 1.5.1 rewrites `mix.json` at its start, so 1.6
  then loads that reduced form. The full 1.6 show is in `/config/mix.json.newer`;
  1.6 names it in `load_warnings` and the banner. Copy it over `mix.json` and
  restart to get it back exactly (changes made in 1.5.1 are lost then).
- **A 1.6 export file does not import into 1.5.x** (its strict import refuses the
  new fields). Roll back with the saved `mix.json`, not with an export.

## What changes for the platform

- **New settings** (all optional, defaults shown):
  - `MIXER_INPUT_DELAY_WINDOW_S` = 300: how long the worst lag of an input counts.
    Lower it if the long hold after a spike hurts more than an odd lost block.
  - `MIXER_INPUT_DELAY_MARGIN_MS` = 1 and `MIXER_INPUT_DELAY_MARGIN_PCT` = 20: the
    margin on top of the worst lag.
  - `MIXER_NUMA_LOCAL` = true: the process opts out of automatic NUMA balancing and
    keeps its memory local. Needs `SYS_NICE` (already granted); without it the mixer
    starts with a WARN. In the lab the DSP thread had 7.6× fewer page faults at its
    start with it.
- **New metrics:** `input_worst_lag_ms{input}`, `input_delay_changes_total`,
  `input_late_events_total`, `dsp_wake_late_seconds`,
  `dsp_thread_page_faults_total{kind}`, `dsp_thread_context_switches_total{kind}`.
  The Grafana dashboard does not have them yet.
- **New status fields:** per input `worst_lag_ms`, `delay_changes`, `late_events`.
- **Deadline misses (D3):** in the lab every miss was the DSP thread woken 2 ms or
  more late, with no preemption, no page fault and blocks well under 1 ms: the host,
  not the mixer's work. The new metrics show this on the platform. CPU isolation of
  the DSP core (and its sibling) is what lowers them further.
- **API additions** (backwards compatible): `PATCH /api/v1/signals` (several strips
  and buses in one change), `POST /api/v1/{strips,buses}/<id>/move`,
  `GET /api/v1/downmix-matrix`; strip patches `{"signal", "tap"?, "channel"}` and
  `{"output", "channel"}`; strip `surround`, `members`, `unlinked`; nodes `fader`,
  `direct-out`, `insert`, `auto`; send taps in the flow; `settings.downmixes`.
- **Loops are refused (D1):** a patch, send, virtual-output source or IS-05
  activation that would close a loop is refused with the loop named (IS-05 answers
  500 with the reason). An IS-05 connection restored at start that would close a
  loop is not restored (WARN in the log).
- **Inserts (C4):** an insert's send is a new MXL flow `<signal>/<node>`; its return
  is a normal input. No delay compensation: the measured round trip is in
  `round_trip_ms`.
- Ports, volumes, CPUs, real time, preview and identity: unchanged.
  `MIXER_READ_OFFSET` stays 2.

## Tested

CI on `main` is green: lint, unit tests, the integration suites and AMWA IS-04-01,
IS-05-01, IS-05-02 and BCP-007-03-01.

Lab, 2026-11-05/06, host 2× Xeon Gold 6136 (SMT on, kernel 6.8, other workloads not
pinned), the CI image `git-0efd0ca`, 1.5.1 for comparison. Platform path: uid 1000,
only `SYS_NICE`, no-new-privileges, `MIXER_RT_PRIORITY=49`, the DSP thread on a core
of its own. The show uses every 1.6 feature: post-fader blocks, several direct outs,
an insert returned through MXL, taps in the flow, surround pans, unlinked members,
a second down-mix, strips reading a bus and a virtual output, 3 Silero VADs and an
auto-mix, 5 virtual outputs, an operator script and a meter client.

| Item | Result |
| --- | --- |
| DSP block time (2 ms blocks) | full 1.6 show **143 µs** (ratio 0.07); the same show without 1.6 features 125 µs against 123 µs on 1.5.1 (+1.4 % median) |
| Deadline misses | full show 1 in 70 min; alternating runs: the same rate as 1.5.1 counted the new way |
| Memory, 70 min | anonymous RSS 63.0 → 63.4 MB, flat (+210 kB/h from 10 min on) |
| Dropouts (D2), same jittered flow, 76 min | ordinary jitter: 1.5.1 34.9 lost blocks/h, **1.6 0**; delay 33 → 42 ms; a 110 ms spike loses about 90 ms of audio on both |
| Local inputs | delay unchanged (3.1 ms) |
| Loops (D1) | refused via the API, show import, IS-05 and later mix changes |
| Rollback 1.6 → 1.5.1 → 1.6 | as described above; `tests/rollback/check-1.5.1.sh` passes |
| AMWA | IS-04-01 39 pass, IS-05-01 53, IS-05-02 55, BCP-007-03-01 55; no failures |
| Integration, all 19 scripts | pass; the one flake (mix.sh) fails as often on 1.5.1 under the same load |
| UI | every tab, no page or console errors |

Found and fixed in the lab run: an insert with a return made the signal after it
add up from block to block (#71); the note on the 1.6 show after a rollback (#70).

Not run: a 24 h soak, real MIDI hardware, the platform's own remote flows.
