# mxl-audio-mixer 1.4.2 — release notes

A smoother start of the inputs, from the 1.4.1 deployment on test-all (losses only in
the first 5 min after a start, while the delays settled). Released 2026-10-23. The
image digest is filled in after the tag build.

## For the platform

- **No setting, metric, API, port or show-file change.**
- **New file `MIXER_STATE_DIR/input-delays.json`** (in `/config`): the last automatic
  delay per flow id, written when it changes. An input starts at it after a restart.
  It is state, not part of the show; deleting it only means the next start measures
  from 0 again.
- **Rollback to 1.4.1 is clean:** 1.4.1 ignores the new file and reads the same
  `mix.json`, inputs and connections.
- `MIXER_READ_OFFSET` stays at the default 2.

## Changes (#47)

- **The last delay per flow (D242).** An input with an automatic delay starts at the
  delay its flow had last (also after a route to another flow, which sets the delay
  back to 0 first). It holds as a floor for one hold time, and an outlier of that size
  recurs at once, so a gateway's rare outliers are covered from the first block. A
  stale high value goes after about 35 s.
- **The start-up phase (D241).** In an input's first minute, until a second outlier
  comes, a late block's short floor and the period of lower need last 5 s instead of
  the hold time: a backlog at the start (a mirror still filling, a first outlier)
  raises the delay at once and lets it fall within about 10 s, not after a minute.
  Outliers that come again get the normal hold, and a recurring one its recurring
  floor.
- **The first lags after 0.1 s (D243).** A new reader (a start or a new route) counts
  its lags after 0.1 s of a head keeping real time (after a stall still 0.5 s): 1.4.1
  read a batched writer at delay 0 for its first 0.5 s.
- `mxl-mixer-tone --start-behind-ms X --catch-up R`; `tests/integration/inputs.sh`
  checks a mirror that starts with a 75 ms backlog.

## Tested

CI on the PR head: unit tests, the EBU loudness cases, the integration suites and
AMWA IS-04-01, IS-05-01, IS-05-02 and BCP-007-03-01. All 16 integration scripts pass
in the lab; `inputs.sh` 5 of 5 in a row.

Lab, 2026-10-23, lab host 2× Xeon Gold 6136, CPUs 43, 45, 47, SCHED_FIFO 49,
`MIXER_READ_OFFSET=2`; writers (`mxl-mixer-tone`, SCHED_OTHER on the same CPUs):
gateway with a +6 ms outlier every 30 s, gateway +5 ms every 40 s, a mirror 12 ms late
starting 75 ms behind and draining at 1.05 times real time, gateway bursts of 5
packets, a browser source (960-sample commits). Samples lost per input in the first
5 min after the mixer started:

| Run | 1.4.1 | 1.4.2 |
| --- | --- | --- |
| fresh start | 576 / 192 / 0 / 10368 / 23232 | 288 / 288 / 0 / 2208 / 6240 |
| restart with the saved state | 192 / 192 / 0 / 11712 / 22848 | 0 / 0 / 0 / 96 / 0 |
| the mirror's backlog delay | up to 27 / 61 ms, down after 60 s | up to 47 / 81 ms, down after 15 / 20 s |

On a fresh start a rare outlier in the first minute may be lost twice (the start-up
phase lets the delay fall before it comes again; then the normal hold or its
recurring floor keeps it). The table was measured before two review changes (a
route to another flow starts over; the short start-up hold ends at a second outlier);
`inputs.sh` covers both. The
hardware runs of 1.4.0 and 1.4.1 stand for the rest: the changes are on the control
side and in the read loop's bookkeeping.
