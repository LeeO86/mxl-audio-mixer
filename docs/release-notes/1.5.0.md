# mxl-audio-mixer 1.5.0 — release notes

The operators' feedback from the Confluence page "Feedback MXL Audio-Mixer": the
console, meters and MIDI control (A1–A10), the processing view and DSP (B1–B6),
the graph, routing and the designer's virtual outputs (C1–C7) and the logic
(D1–D4); the fix of the Silero VAD memory leak (test-all OOM every ~2.75 h) and
constant-memory loudness; tolerant loading of a show from a newer version.
Released 2026-10-30.

## Upgrade and rollback — read first

- **Export the show before upgrading:** `GET /api/v1/config/export` (or keep a copy
  of `/config/mix.json`). An upgrade from 1.4.x is in place (the same `/config` and
  output domain). A 1.4.x `mix.json`, show file, inputs and IS-05 connections load
  unchanged.
- **Upgrade, one behaviour change in the logic:** a fader block feeding an on/off
  input is now on from its `threshold_db` (default **0 dB**; before: from +0.5 dB).
  Check live graphs with faders standing at 0 dB.
- **Rollback to 1.4.x loses the mix once 1.5.0 features are used.** 1.4.3 then
  does not refuse to start: it renames the file to `/config/mix.json.bad` and
  **starts with an empty mix** (the input routes stay). Measured on 1.4.3, each on
  its own:

  | 1.5.0 feature in the mix | 1.4.3 |
  | --- | --- |
  | a virtual output with a source (bus, direct out, monitor, input) | `.bad`, empty |
  | a `leveler` node | `.bad`, empty |
  | a send's surround `pan` | `.bad`, empty |
  | a surround panner with `elevation_deg` above 0, or layout 5.1.4 / 7.1.4 | `.bad`, empty |
  | an output `tap` other than the default | `.bad`, empty |
  | a logic `set-route` block (D4) | `.bad`, empty |
  | a TSL out without an index (`null`, D3) | `.bad`, empty |
  | a webhook with an empty URL (D3) | `.bad`, empty |
  | a fader block's `threshold_db` (D1) | loads; the threshold is **dropped**, the trigger goes back to +0.5 dB |
  | an input alias (C2) | loads |

  To roll back, first silence every virtual output
  (`DELETE /api/v1/virtual-outputs/<n>`), delete set-route blocks, give TSL outs an
  index and webhooks a URL (or delete them), remove `leveler` nodes, send pans
  (`{"pan": null}`) and output taps, set panners back to 5.1/7.1 at 0°; or restore
  the show exported before the upgrade. With all of that removed, 1.4.3 loads the
  1.5.0 `mix.json` (measured). The 1.4 mixer has no virtual outputs: the designer's
  wiring to them goes dead.
- **From 1.5.0 on, a rollback keeps the mix** (D279): a `mix.json` or show-history
  version written by a newer version loads without what this version does not know
  (unknown fields, chain nodes, logic blocks with their wires); the original stays
  as `mix.json.newer`, the dropped paths are logged once (WARN), listed in
  `GET /api/v1/status` `load_warnings` and shown in a dismissible banner. A wrong
  type or a missing field still goes to `mix.json.bad`.

## What changes for the platform

- **New settings for the designer's outputs (C7):**
  - `MIXER_OUTPUTS`: JSON array, one entry per virtual output,
    `{"key": "pgm", "label": "PGM", "format": "5.1"}`, all optional (key: the slot
    number; label "Output <n>"; format stereo). `key` (`a-z`, `0-9`, `-`, 1–32
    characters, not only digits, unique) names the output's ids and its source in
    the mix, so reordering the list keeps both. Formats: mono, stereo, 3.0, 5.1,
    7.1, 5.1.4, 7.1.4. Also in `MIXER_CONFIG_FILE` as a JSON array.
  - `MIXER_OUTPUT_FLOWS`: number of virtual outputs, 0–64 (default: the length of
    `MIXER_OUTPUTS`, else 0). Each takes one of the 128 output slots first; the
    published outputs and monitors share the rest.
  - Every virtual output is an MXL flow in the own domain and an NMOS Source, Flow
    and Sender, there from the start whatever the mix, silent until the operator
    picks a source (a bus, a strip's direct out, a control-room monitor clean or
    speaker feed, or an input straight through).
- **NMOS ids and labels:** sender id = UUIDv5(node id, `"sender:out-vout:<key>"`),
  MXL flow id = UUIDv5(NAMESPACE, `"<NMOS_SEED>/output/vout:<key>/mxl-flow"`): stable
  across restarts and reordering (measured). The Source/Flow/Sender label is the
  configured label as given; the node label is `NMOS_LABEL`. **Labels are unique**
  (trimmed, case-sensitive, also against "Output <n>"): two equal labels in
  `MIXER_OUTPUTS` stop the start; publishing or renaming a strip, bus or monitor to
  a virtual output's label (or two to one label) is refused (400). A clash an older
  saved mix already has is a WARN at the start and listed in `label_clashes` of
  `GET /api/v1/status`.
- **New metric** `mxl_audio_mixer_virtual_output_routed{slot,output,label}` (1 with
  a source, 0 silent; `output` is the key or the slot).
- **New status fields:** `virtual_outputs` (slot, id, key, label, format, source,
  sender and flow ids, running, errors, commit lag), `load_warnings` (D279),
  `label_clashes`; `outputs[].virtual_output` (the slot, `null` for a published
  output).
- **Behaviour change of a metric (A3):** `mxl_audio_mixer_true_peak_dbtp{signal}`
  and `GET /api/v1/meters` (also the far side's meters over the remote link) now
  show a **muted strip's level**, not silence. Logic Level and Above blocks still
  read a muted strip as silent.
- **C2, the input's connected name:** the mixer looks up the IS-04 sender label of
  each routed input in the registry's Query API (v1.3,
  `NMOS_QUERY_ADDRESS`/`NMOS_QUERY_PORT`, default the registry and registration port + 1), when the route changes and at most once a minute per input, with a backoff of 5 s – 1 min when
  it does not answer; else the MXL flow's label. It uses the environment's proxy
  settings: `NO_PROXY` must cover the registry if a proxy is set.
- **Memory:** the Silero leak (about 16 kB/s per detector, 1 GiB OOM about every
  2.75 h on test-all) and the growing loudness history are fixed; the memory limit
  can stay at 1 GiB.
- **API additions** (all backwards compatible): `/api/v1/virtual-outputs`,
  `GET /api/v1/flows`, `PUT /api/v1/inputs/<n>/route`, `label` (alias) on
  `PATCH /api/v1/inputs/<n>`, `connected_label`/`sender_id` on inputs, `pan` on
  sends, `tap` on outputs, the `leveler` node, `elevation_deg` and layouts 5.1.4 /
  7.1.4 on `surround-pan`, `band_reduction_db` and `leveler_gain_db` in the node
  meters, logic `set-route` and `threshold_db` on fader blocks.
- Ports, volumes, CPUs, real time, preview and identity: unchanged (see
  `docs/release-notes/1.3.0.md`, "What the platform must set" and "Catalog facts").
  `MIXER_READ_OFFSET` stays 2.

## Changes

### Console, meters and MIDI (A1–A10, #54)

- The browser tab title names the tab and the node (A1).
- Strips of 7.1 and wider are wider with narrower meter bars, the fader stays
  usable (A2); a muted strip's meter shows its level in grey (A3); gear and ⋮ in the
  format row (A4); click the fader value to type a level (A5); the strip shows send
  levels only, a click opens Routing (A6).
- MIDI control from the browser (A7): Mackie Control (banks of 8, motor faders,
  mute, solo, select, V-pot pan, master, display, extender) and generic MIDI learn
  (kept per browser, export/import JSON).
- Surround picture on strips with a panner, draggable (A8); narrower multichannel
  meters with channel labels (A9); the panner reaches 5.1.4 and 7.1.4 with a height
  (A10).
- The meter tick no longer runs back-to-back after a late tick (wide signals
  flickered to −∞, logic level blocks saw false edges). Faster gain steps on the
  DSP thread.

### Processing and DSP (B1–B6, #53)

- Copy and paste of processing units (B1); per-band gain reduction of multiband
  and dynamic EQ (B2).
- New **`leveler`** node for buses and streams (B3): slow gain riding to a
  short-term loudness target, gate, max gain/cut, speed, optional 1 ms safety
  limiter (inspired by the idea of master_me; own code).
- Flow view below the chain: reorder nodes, move sends, direct/bus out and keys to
  another tap (B4); the spread bubble of the surround panner (B5); a per-send
  surround pan for mono or stereo sources into 5.1 or wider (B6).

### Graph, routing, virtual outputs, aliases (C1–C7, #52, #59, #60)

- The graph's send panel edits a send's surround pan or the target's down-mix (C1);
  inputs show what is connected and take an alias, inherited by their strips (C2);
  an input's MXL flow is chosen in the graph (C3); double-click opens processing or
  the control room (C4); the graph keeps its view over a tab switch (C5).
- Control-room monitors can feed a virtual output, clean or speaker feed (C6).
- **Virtual outputs** (C7): the designer's fixed outputs, fed by a bus, a direct out,
  a monitor or an input; drawn like published outputs in the graph and routing;
  unique NMOS labels (#59); keyed outputs recognised in the status (#60: before, the
  graph drew them twice).

### Logic (D1–D4, #51, #55)

- A fader block has a threshold (`threshold_db`, the "High at" column) (D1).
- "Copy logic to" a new or existing graph; paste renames only clashing ids (D2).
- Webhook and TSL out drop onto the canvas like every block; an empty URL or index
  is inert until set (D3).
- Action "Route input → output" (`set-route`): while on, a virtual output takes the
  input straight through; off clears it if it still has that input (D4).

### Memory and loading (#56, #57, #58)

- **Silero VAD leak fixed:** `ort` 2.0.0-rc.14 leaked an `OrtTypeInfo` for every
  output tensor it created, two per inference; the outputs are now preallocated.
- **Loudness** measurements keep histograms of 0.1 LU bins instead of every block:
  constant memory and time, the same results (within 0.003 LU integrated,
  0.042 LU LRA).
- **Tolerant show loading** (D279), above.
