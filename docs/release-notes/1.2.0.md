## Changes

- **Logic graphs** in the show (§11), evaluated at 100 Hz; the Logic tab draws
  the cables and lists the same graph under them; `/api/v1/logic`.
  - Blocks: constant, button (a soft key), a signal's mute, fader, voice and
    level, tally on air, timer, above (a meter threshold with hysteresis),
    snapshot recall, AND, OR, XOR, NOT, compare, edge, latch, delay, debounce,
    schedule (UTC minute of the day), webhook (POST when the input rises),
    set-mute, set-fader.
  - A loop is allowed only through an edge, a latch, a timer, a delay or a
    debounce. Actions run when their input changes; `dry_run` computes without
    acting. Logic is not part of snapshots.
- From 1.1.0: VAD (Silero by default), auto-level, gain-sharing auto-mix,
  ducking (fixed and ratio), `input_overrun_samples_total`, and the ports below.

## Ports and volumes

| Port | Default | |
| --- | --- | --- |
| `WEB_PORT` | 8190 | web UI, API, events WebSocket, probes, metrics |
| `NMOS_PORT` | 3342 | IS-04 Node API, IS-05 Connection API. 3343 is reserved for IS-07 events and not opened. |
| `TSL_UDP_PORT` (udp), `TSL_TCP_PORT` | 8910, 8911 | TSL UMD 5.0 tally, only with `TSL_ENABLE=true` |
| `MEDIAMTX_RTSP_PORT`, `MEDIAMTX_WHEP_PORT`, `MEDIAMTX_ICE_UDP_PORT` (udp) | 8954, 8599, 8199 | the built-in MediaMTX, only without `PREVIEW_PUBLISH_URL` |

Volumes as in 1.0.0: `/config` (writable, persistent) and the MXL root at
`/Volumes/mxl` (hostPath).

## Widgets and exit codes

Unchanged since 1.0.0: `strip`, `fader-bank`, `loudness`, `monitor`,
`talkback`, `vca`; exit codes 0, 75, 78, 143.

## What the platform must set

As for 1.0.0 (`docs/release-notes/1.0.0.md`), with the ports above. The DSP
thread needs its CPU's whole physical core: the static CPU manager with
`full-pcpus-only` (or SMT off), and `reservedSystemCPUs` covering the system
daemons, so that no unpinned pod runs on the DSP core's sibling.

## Tested

In CI on the tag (GitHub runners): the CI and publish runs passed (unit tests,
the EBU loudness cases, the integration suites through libmxl and the
nmos-cpp registry, AMWA).

On hardware (the maintainers, 2026-10-15/16): `tests/hw/release/run.sh env
block-clock load registry` (`LOAD_MINUTES=30`, `BLOCK_MINUTES=10`) on the tag's
checkout, `target/release` rebuilt (binary sha256 `fdae65a067e8a7b5…`), then
`amwa` in its own container. 2× Xeon Gold 6136 (48 CPUs, SMT on), kernel 6.8
generic (voluntary preemption), no isolated CPUs, other unpinned media
workloads on the host. The runner had 12 CPUs of socket 2: CPU 21 and CPU 45
(one physical core) plus 25–43 odd. The DSP thread took CPU 45 at
SCHED_FIFO 49 and the mixer kept its 15 other threads off CPU 21 (`a core of
its own (its other CPUs kept free)`). The eight §16 tone writers were set to
SCHED_FIFO 45 on CPUs 39–43 from outside the script.

The deadline misses against the load on the DSP core's sibling (CPU 21), one
sample a second over the load:

| Sibling busy | Seconds | Misses | Per second |
| --- | --- | --- | --- |
| 0–3 % | 997 | 1 | 0.001 |
| 3–6 % | 357 | 2 | 0.01 |
| 6–10 % | 42 | 10 | 0.24 |
| 10–20 % | 56 | 106 | 1.89 |
| ≥ 20 % | 176 | 1 | 0.01 |

With the sibling idle there was 1 miss in about 17 minutes, ten times better
than the shared core of 1.0.0. The rest came while another workload's
memory-heavy video writer ran on the sibling (28 of the last 42 misses in its
58 s); a compiler keeping the sibling near 100 % busy caused none. The mixer
caused none of the sibling's load. With the tone writers real-time, the late
reads fell to 0.13 a minute (2.75 a minute on `7ea4077`).

**Still open:** the 0-misses rule on a node whose DSP core's sibling is really
free (`full-pcpus-only`); this host cannot keep it empty.
